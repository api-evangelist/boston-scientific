## What an agent can and cannot do here

Boston Scientific publishes **no HTTP API**. There is no OpenAPI, no AsyncAPI, no GraphQL SDL, no
WSDL, no MCP server, no A2A agent card and no developer portal. An agent cannot call this company.

What the company does publish is a **healthcare-messaging integration contract**, distributed as
PDF specification documents, for getting implanted-device observations out of its LATITUDE remote
patient monitoring system and into a hospital EMR. That contract is real, versioned and grounded
in named international standards — it is simply not machine-readable and not callable.

## Integration contract (HL7 v2 / IHE PCD, PDF)

- [LATITUDE Integration IDCO and HL7 Specifications](https://www.bostonscientific.com/content/dam/elabeling/crm/pr/359483-012_LATITUDE_CM_en_S.pdf): The full message specification. Declares two profiles — an IDCO profile that is a PCD-09 message per IHE PCD Technical Framework Revision 3.0, carried as a standard HL7 v2.6 unsolicited orders and observations message (ORU^R01^ORU_R01), and a LATITUDE HL7 file profile based on the HL7 2.3.1 Observation Result Unsolicited message (ORU^R01). Includes segment structures and complete worked example messages.
- [LATITUDE NXT IDCO Specification](https://www.bostonscientific.com/content/dam/elabeling/crm/pr/359273-011_LATITUDE_NXT_IDCO_en-GBR_W_S.pdf): The IDCO-only edition of the same contract.
- [LATITUDE EMR Integration solutions overview](https://www.bostonscientific.com/content/dam/bostonscientific/Rhythm%20Management/portfolio-group/LATITUDE/PDFs/CRM-922306-AA_Latitude_EMR_Integration_solutions_EN.pdf): Product-level description of the EMR integration.
- [Instructions for Use / eLabeling](https://www.bostonscientific.com/ifu): Where Boston Scientific directs readers to find the current integration specification documents.

Observation codes use the ISO/IEEE 11073-10103:2014 IDC nomenclature (e.g.
`MDC_IDC_SET_BRADY_MAX_TRACKING_RATE`). Message character set is declared in MSH-18; message
correlation is MSH-10.
